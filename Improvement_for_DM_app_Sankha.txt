***** AI-powered Bluetooth diagnostic engine for DM devices *****

Instead of static FAQs, build a system that:

- Understands user problem in natural language
- Uses device-specific troubleshooting knowledge
- Guides step-by-step resolution
- Optionally reads logs/screenshots.


*** Smart Troubleshooting Guide (Primary Goal):

Large Language Model (LLM) + RAG system trained on:
- Bluetooth troubleshooting docs
- Known issues like API not working or other error codes
- Device specific compatibility rules.

In-App AI Assistant Flow:

- User opens app --> Sync happens
- If sync fails - show “Having trouble?” on UI
- Clicks “Having trouble?”
- Chat UI appears (like ChatGPT)
- User types his problem (provided the basic device details will be automatically captured without asking user every time)
Add context automatically. Instead of asking user everything:
{
  "device": "Samsung S21",
  "os": "Android 14",
  "bluetooth_state": "ON",
  "is_paired": true
  "ds_device_info" : "D1234567890123"
}

- The query goes to backend.
- Search in the DB whether any relevant context/answer is present or not based on user's question/problem.
Suppose, users says:
“My DreamStation device not connecting to Android. Every time asking for pairing popup.”

- If answer is present in DB, return the result.
 LLM generates result:
 1. Go to Settings → Connections → Bluetooth → Tap “Forget device”.
 2. Pairing failed due to authentication timeout. Try clearing bonded devices and re-pair.
 3. API fails - No need to worry it's not Bluetooth issue! Due to some maintenance work in backend some services are down.
...

- If Not present (new problem), ask the AI bot to generate some relevant answer or create a ticket in support with the issue details + capture the issue for future reference to the model.

*** Responses should be split into 2 categories:

1. Verified (from DB)
- Known issues
- Backend outages
- Firmware bugs.

2. Generated by LLM model (using Gemini or any other APIs)
- Generic troubleshooting,
- Step-by-step guidance.
